# Forward Deployed Engineer research

**Career comparison:** Forward Deployed Engineer (FDE), an AI-enabled, customer-facing engineering role.  
**Research checked:** November 5, 2026.

## Current example posting

[OpenAI — Forward Deployed Engineer (FDE), Healthcare — NYC](https://openai.com/careers/forward-deployed-engineer-%28fde%29-healthcare-nyc-new-york-city/)

The posting describes work with healthcare organizations to take AI systems from customer discovery and workflow scoping through architecture, hands-on implementation, evaluation, production deployment, adoption, and handoff. It emphasizes translating complex customer workflows and constraints into technical systems, measuring operational impact, working with customer and internal teams, and turning deployment lessons into reusable patterns.

The specific NYC healthcare role lists **6+ years of relevant experience**, senior-level technical ownership, healthcare workflow knowledge, and travel up to 50%. It is a senior, specialized example, not an entry-level target. Requirements differ across FDE jobs, locations, and industries.

## PM and FDE: shared focus, different work

| | Product Manager | Forward Deployed Engineer |
| --- | --- | --- |
| Main question | Which user problem and product outcome should the team prioritize? | How can a technical system solve this customer's workflow reliably in production? |
| Common activities | Research, product direction, tradeoffs, roadmap, success measures, cross-team alignment | Technical discovery, architecture, coding/integration, evaluations, deployment, adoption, handoff |
| Useful strengths | Listening, clear communication, prioritization, collaboration, interpreting evidence | Software engineering, systems thinking, customer communication, implementation, evaluation |
| Portfolio evidence | User problem, decision, roadmap choice, prototype, feedback, measured learning | Working technical prototype, system diagram, integration/evaluation plan, safe test data, deployment/monitoring notes |

The OpenAI posting is one employer's description; other FDE titles may mean different levels of engineering, customer travel, or domain specialization.

## A realistic learning exercise

A future student exercise could map a simple, fictional customer workflow, build a small prototype, and define a test for reliability or usefulness using synthetic information. This would help practice technical problem framing and evaluation. It would be a learning exercise—not equivalent to shipping a production AI system, handling healthcare data, or meeting the experience requirement in this posting.

The existing T-shirt website can support the **user discovery and communication** side of a case study. By itself, it does not establish the production engineering depth requested by this specific FDE role.
